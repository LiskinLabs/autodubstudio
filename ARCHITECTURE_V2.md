# AutoDubStudio (V2) - Архитектура и Roadmap

## 1. Концепция и Принципы
*   **Локальность:** Приложение должно максимально использовать локальные вычислительные мощности (Ollama, XTTS, Qwen3).
*   **Стабильность (VRAM Management):** Строгое правило "Одна модель за раз". Никаких параллельных запусков LLM и TTS. Между этапами очищается кэш CUDA (`torch.cuda.empty_cache()` и `gc.collect()`). Для железобетонной стабильности тяжелые модели (Qwen3, F5, Whisper) запускаются в изолированных подпроцессах Python.
*   **Качество важнее скорости:** Мы жертвуем скоростью синтеза ради студийного качества на слабых ПК (RTX 3050 4GB).

## 2. Текущий Конвейер (Pipeline)
1.  **Скачивание/Извлечение:** Загрузка видео с YouTube (`yt-dlp`), конвертация в WAV.
2.  **Разделение звука:** `Demucs` (модель `htdemucs`) для извлечения чистой речи (`vocals.wav`) и фоновой музыки (`no_vocals.wav`).
3.  **Распознавание речи:** `Faster-Whisper` для создания SRT субтитров.
4.  **Диаризация (Определение спикеров):** Разделение на Спикер 1, Спикер 2 и т.д. (через `pyannote.audio` или альтернативы).
5.  **Перевод (LLM):** `Ollama` (Gemma 2, Llama 3) для качественного перевода с учетом контекста.
6.  **Локальная озвучка (TTS):** Генерация речи (батч-обработка через JSON-файлы).
    *   **XTTSv2:** Идеально для турецкого языка (4-5GB VRAM). Поддерживает кросс-языковое клонирование.
    *   **Qwen3-TTS:** Отличное качество для RU, EN. Не поддерживает турецкий язык.
    *   **F5-TTS:** Передовая модель для Zero-Shot клонирования (нужен CPU offloading для 4GB VRAM).
7.  **Укладка и рендер:** Склейка озвучки с фоновой музыкой и рендеринг видео (`ffmpeg`).

## 3. Идеи для будущего внедрения (Roadmap)

### 3.1. Изоляция тяжелых ИИ в подпроцессы (Оптимизация памяти)
Вдохновившись `pyVideoTrans`, нам нужно запускать *все* этапы (Распознавание, Перевод) как изолированные Python-скрипты через `subprocess.run()`. Это гарантирует 100% освобождение VRAM на слабых картах. На данный момент так работают только TTS (XTTS, F5, Qwen3).

### 3.2. Динамическое извлечение референсов (Умный Voice Cloning)
Вместо того чтобы просить пользователя загрузить `ref_audio.wav`, система должна сама:
1. Брать таймкод каждой реплики из SRT.
2. Вырезать этот кусочек из `vocals.wav` (оригинальный голос от Demucs).
3. Передавать его как референс (эталон) в XTTS/F5.
*Итог:* Система автоматически сохранит оригинальные эмоции и голоса разных спикеров без сложной настройки!

### 3.3. Режим "Ручной проверки" (Интерактивный перевод)
Добавить флаг/кнопку паузы после шага перевода. Скрипт останавливается и просит пользователя открыть `translated.srt`, исправить ошибки перевода (ведь ИИ не идеален), и нажать "Продолжить" для старта озвучки.

### 3.4. Автоматическая подгонка по времени (Time-stretch)
Интеграция удаления пауз (`silence` из сгенерированного TTS звука) и небольшое ускорение/замедление аудио через `pydub`, чтобы оно идеально вписывалось во временные рамки субтитра (Lip-Sync база).

### 3.5. Модуль Live Translate
Прямой перевод встреч/видео на ПК с выводом переведенных субтитров поверх всех окон в реальном времени.

## 4. Отклоненные или устаревшие идеи (Удалено из планов)
*   *ОДНОВРЕМЕННАЯ работа перевода и озвучки.* (Отказ из-за жестких лимитов в 4 ГБ VRAM).
*   *Обучение собственных LoRA для голосов.* (Слишком сложно для рядового пользователя. Заменено на Zero-Shot подходы вроде F5-TTS).
*   *Синхронизация губ (Wav2Lip / Video Retalking).* (Отказ. Требует от 8-12 ГБ VRAM, не вписывается в концепцию доступности для 4GB GPU).
